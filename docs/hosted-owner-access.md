# Hosted SHY owner access

v0.105.21 prepares the existing SHY application for an owner-only hosted installation. It does not add customer signup or separate authenticated project accounts.

The Next.js frontend requires HTTP Basic owner credentials in hosted mode (`SHY_REQUIRE_AUTH=1` or `RENDER=true`). Set `SHY_OWNER_USERNAME`, a strong `SHY_OWNER_PASSWORD` of at least 8 characters (longer passwords are recommended), `SHY_PUBLIC_ORIGIN` to the exact HTTPS service origin (or use Render’s `RENDER_EXTERNAL_URL`), and a random `SHY_ACCESS_TOKEN` of at least 32 characters. Missing hosted configuration fails closed. All frontend pages and API routes require owner access; writes require the matching Origin. Responses are private/no-store and not indexed. The password and API token are server-only environment variables, never NEXT_PUBLIC values.

The core requires the matching Bearer token on every endpoint except `GET /livez`, which reports only process liveness. Frontend proxies attach the token to backend requests; caller-provided credentials are not forwarded. Keep the token out of URLs and logs. Local installations without hosted configuration retain their existing localhost defaults. Projects remain local scopes within a single owner installation; sharing the owner password shares access to that installation.

Deploy the current GitHub main branch using `Dockerfile.hosted` and `render.yaml`. The already-provisioned `shy-db` must exist in the same Render workspace. The Blueprint references its connection string and generates both secrets without placing them in the repository. Choose **main** explicitly in the Blueprint creation flow; the repository’s historical default branch may differ. The image runs a loopback-only core and the protected frontend on Render’s PORT. Its supervisor stops both processes if either fails and forwards termination signals. Frontend startup waits for the core; `/livez` is minimal public process liveness, not proof of model health. The owner username is `owner`; retrieve `SHY_OWNER_PASSWORD` in the service’s Render Environment settings. No new database or paid compute plan is declared by the Blueprint.

A Render deployment does not automatically connect to Ollama on the owner's Windows laptop. Without a reachable configured engine, health reports degraded, general generation fails, and deterministic features can still work. Do not substitute fake answers or present an unavailable engine as healthy. Browser voice support varies; local speech transcription and document-model generation require their configured engines.

Free Render web instances sleep on idle; the free PostgreSQL instance expires after 30 days and has no backups. This initial hosted preview needs a durable paid database or a migration before expiry for continued use. No paid upgrade is implied by this configuration.
