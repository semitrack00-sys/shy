# Explicit public research requests

v0.105.19 adds the collapsed **Research public sources** panel and a typed `research_request` on `/chat` and `/agent`. Submitting it sends only the question to the existing configured public search pipeline, without requiring an English research prefix. The pipeline still requires a working provider and retains authoritative-evidence and citation checks. Existing direct generation and calculator/tool action dispatch are bypassed for this explicit research question.

The object requires exactly one `freshness` enum: `auto` uses the existing fixed multilingual phrases; `same_day`, `past_week`, `past_month` choose 0, 7, 30 UTC calendar days; `any_date` removes the freshness requirement. Explicit choices override question phrases and record `user_selected` in answer context. Any date permits historical or undated evidence but never invents missing source text or accepts invalid citations. Provider dates remain estimates and retrieval time never proves publication time. No other action, task/approval/cancellation control, document question or option comparison can be combined. Explicit public research rejects `local_only`; the query is limited to 1–1000 trimmed characters. Malformed controls fail before conversation creation or message writes.

The form is separate from ordinary messages and voice sending. It resets with a new conversation and disables while sending. User selections, the exact research question, and public answer context are retained in browser history; failed retries retain that question and date choice. Server message history retains textual questions and replies, not the structured browser metadata. Local project conversation ownership still applies. This does not add account authentication, unrestricted tools, full-page retrieval or measured model/source truth accuracy. Sequential v0.150 remains incomplete.
