# Reviewed reply defaults

v0.105.17 adds `GET/PATCH /memories/response-preferences?project_id=...` and a **Review reply preferences** control in settings. Language choices are current-message language, English, French, Haitian Creole, Spanish, Brazilian Portuguese, Korean and Swahili; detail is short/standard/detailed, and tone is plain/formal. Only these enums are accepted. No free-form system prompt override is stored.

Defaults are disabled and unreviewed until explicitly saved with boolean confirmation and the current revision. Saves use a project-specific transaction lock and compare-and-set revision. Concurrent stale reviews fail with 409. Disabling retains a new revision rather than deleting the row, preventing old revisions from becoming valid again. The reply settings and automatic-memory-saving settings use separate records and revision counters.

Chat and agent requests load only their effective local owner’s settings. A ContextVar holds the request’s profile during core generation and is reset even on exceptions; concurrent requests do not share mutable profiles. Enabled defaults add predefined instructions to the core generation system prompt and require local Ollama generation. Hosted candidates are filtered even if routing labels are inconsistent; local model failure does not send the saved defaults to a hosted fallback. Existing approved web searches still use their usual question/evidence flow, without passing the reply defaults to the search provider. Current explicit user instructions take precedence; quotations, citations, calculations, machine-readable formats and safety boundaries are preserved by instruction. No tool approval, account access or data-sharing authorization changes.

The response reports whether preference instructions were attached to generation and always reports `output_style_verified: false`. This is prompt provenance, not a claim that a model followed the requested language, length or tone. The browser validates this metadata and persists it in local history. Purely deterministic calculator, selected-document and system replies keep their existing text and do not claim that a preference prompt was applied. If settings cannot be loaded, generation retains its usual defaults and the response indicates that preferences were unavailable. Direct generation helpers outside chat/agent do not infer a user profile.

The UI reads settings only when opened, invalidates confirmation after edits, and requires fresh review after stale-write rejection. Project switching remounts the settings control. Local project names are not account authentication.

Checks include bounded enum input, confirmation, durable persistence, project separation, concurrent writes, disable/re-enable revision progression, concurrent generation contexts, context reset on exceptions, actual chat/agent prompt construction with a fixture generation provider, unchanged decimal replies, safe database errors, browser controls, provenance and history persistence. These qualify integration behavior; real multilingual model output and representative style accuracy remain unmeasured. Roadmap v0.116 remains partial, and v0.150 is not complete.
